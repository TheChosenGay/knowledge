# 频道成员列表设计 - 我的答案

> 提交时间：2026-04-23

## 1. 实体设计

```
struct User {
    userId
    Name
    // 各种用户信息
}

struct Guild {
    Id
    Name
    Creator: userId
    Owner: userId
    members: []userId  // 成员少时内联，成员多时单独建 GuildRelation 表
}
```

## 2. 服务拆分

### GuildUserService
```
fetchUsers(guildId, offset) -> []Users   // 获取成员列表（分页）
```

### GuildManageService
```
KickoutUser(guildId, userId) -> bool     // 踢出成员
SetGuildManager(guildId, userId) -> bool   // 设置管理员
UnsetGuildManager(guildId, userId) -> bool // 取消管理员
```

### GuildAuthService
```
IsGuildOwner(guildId, userId) -> bool
IsGuildManager(guildId, userId) -> bool
IsGuildMember(guildId, userId) -> bool
```

### GuildSearchService
```
lookForUser(guildId, userName) -> []Users
```

## 3. Repo 层抽象

```
interface GuildUserRepo {
    fetchUsers(guildId, offset) -> []Users
    AddUser(guildId, userId)
    // ...
}
```

各 Service 依赖 `GuildUserRepo` 接口，底层可以是 MySQL 实现或 Redis 实现，可替换。

## 4. 存储

- 用户信息、频道信息存 **MySQL**
- 成员数少时，成员列表内联在 Guild 表；成员数多时，单独建 **GuildRelation 表**
- 搜索：按频道 id + 用户昵称建索引；热频道成员列表用 **Redis 缓存**

## 5. 权限校验

- 请求经过中间件确认身份后，`GuildManageService` 在执行踢人/设置管理员时，额外调用 `GuildAuthService` 确认当前操作者是 owner 或 manager

## 6. 客户端架构

- iOS/Android：**MVVM**，ViewModel 负责调用各 Service、管理数据、触发 UI 刷新
- SwiftUI 场景下数据变更自动响应视图更新
- 网络层统一封装，不同业务走不同 API 路由
