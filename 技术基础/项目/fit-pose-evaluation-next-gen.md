# 姿态评估下一代方案：绕过角度精度瓶颈

## 核心问题：角度不可靠

基于 2D 关键点计算的角度存在系统性误差，误差来源无法通过平滑消除：

| 误差来源 | 量级 | 能否通过平滑解决 |
|----------|------|-----------------|
| **2D 投影畸变** | 10-30° | ❌ 系统性偏差 |
| **关键点抖动** | 3-8°/帧 | ✅ EMA 可缓解 |
| **遮挡猜测** | 15-40° | ❌ 模型瞎猜 |
| **低置信度输出** | 不确定 | ❌ 需要过滤 |

当阈值为 10°（如"膝盖角度偏差>10° 才反馈"），而测量误差本身就有 10-30°，反馈变成随机噪声。

**核心洞察：与其追求把角度算准，不如设计一个不强依赖角度精度的评估架构。**

---

## 替代方案

### 方案 1：Pose Embedding 相似度（推荐实时层）

不计算单个关节角度，直接比较"姿态整体形状"：

```
用户 pose (17 关键点坐标)
    ↓ normalize (hip 居中 + torso 缩放)
    ↓ flatten → 34 维向量
    ↓ cosine similarity vs 标准 pose 向量
    → 相似度 0.0~1.0
```

**优势：**
- 不依赖任何单个关节精度 — 一个点偏了，整体只掉一点
- 天然容忍抖动和小误差
- 不需要定义"哪个角度该多少度"
- 计算极快（一次点乘）

**定位问题关节：** 整体相似度低时，逐关节计算贡献度（屏蔽某关节后相似度变化量），贡献度最大的就是问题关节。

**局限：**
- 2D embedding 仍受视角影响（同一姿势侧面看向量不同）
- 解决：3D 关键点做 embedding，或拍摄时固定视角

### 方案 2：VLM 直接判断（推荐深度分析层）

完全跳过角度计算，把骨架可视化发给多模态模型：

```swift
let image = renderSkeletonOverlay(frame, joints)
let prompt = """
这是用户做\(exerciseName)的骨架图。
指出最需要纠正的 1-2 个问题，给出具体建议。
"""
```

**优势：**
- 零规则编写，零样本覆盖所有动作
- 利用 VLM 内化的运动学常识
- 不依赖本地角度计算的精度

**局限：**
- 延迟 1-2 秒，不能帧级实时
- 成本（但每 3-5 秒一次可接受）
- 精度取决于 VLM 能力（可能对微小偏差不敏感）

### 方案 3：置信度门控 + 多帧共识（现有方案增强）

如果仍保留角度计算，必须加两层保护：

```swift
// 层1：只信任高置信度点
guard joint1.confidence > 0.7,
      joint2.confidence > 0.7,
      joint3.confidence > 0.7 else { return nil }

// 层2：连续 N 帧一致才触发（排除瞬时噪声）
if deviationHistory.suffix(5).allSatisfy({ $0 > threshold }) {
    triggerFeedback()
}
```

## 推荐架构：双层评估

```
┌─────────────────────────────────────────────┐
│ 实时层（每帧，<50ms）                         │
│                                             │
│  Pose Embedding 相似度                       │
│  → 整体评分 0-100                            │
│  → 贡献度最大关节 = 问题关节                   │
│  → 触发条件：连续 10 帧相似度 < 0.85          │
│  → 输出：即时语音提示（"注意膝盖"）            │
└──────────────────────┬──────────────────────┘
                       │ 每 3-5 秒
┌──────────────────────▼──────────────────────┐
│ 深度分析层（周期级）                           │
│                                             │
│  最近一个动作周期的 pose 序列摘要              │
│  → 发送给 LLM/VLM                           │
│  → AI 用自然语言描述具体问题和修正建议         │
│  → 不依赖本地角度值，角度仅作辅助参考          │
│  → 输出：详细语音指导（"下蹲时重心偏前..."）   │
└─────────────────────────────────────────────┘
```

**角色分工：**
- 实时层：快速判断"有没有问题" + "大概在哪"
- 深度层：精确诊断"什么问题" + "怎么改"
- 角度值：降级为 AI 的辅助参考信息，不再作为评分的唯一依据

## 运动学特征补充（不依赖绝对角度精度）

| 特征 | 检测什么 | 计算方式 |
|------|----------|----------|
| 角速度 | 动作匀速/失控 | 相邻帧角度差分 |
| 加速度 | 代偿发力 | 角速度差分 |
| 轨迹方差 | 稳定性 | 关节位置在时间窗口内的标准差 |
| 对称性 | 左右差异 | 左右对称关节的欧氏距离差 |

这些特征的优势：**基于相对变化而非绝对值**，投影畸变对差分的影响远小于对绝对角度的影响。

## 数据驱动闭环：VLM → 本地蒸馏

```
阶段 1：VLM 零样本判断（无需训练数据）
    ↓ 积累 VLM 的判断结果作为标注
阶段 2：训练本地轻量分类器（<1MB）
    ↓ 输入：pose 序列 → 输出：错误类型
阶段 3：本地实时 + VLM 仅做边界 case 仲裁
```

## 现有方案 vs 升级后

| 维度 | 现有（规则+角度） | 升级后（embedding+VLM） |
|------|-------------------|------------------------|
| 角度精度依赖 | 强 | 弱（embedding）/ 无（VLM） |
| 新动作接入 | 手写规则（小时级） | VLM 零样本（分钟级） |
| 视角鲁棒性 | 差 | 3D embedding 或 VLM 解决 |
| 误报率 | 高（噪声触发） | 低（多帧共识 + 整体评估） |
| 反馈质量 | "动作不标准" | "膝盖内扣约15°，重心偏前" |

## 落地优先级

1. **Pose Embedding 相似度** — 替代逐关节角度评分，改动集中在 ExerciseFormEvaluator
2. **多帧共识 + 置信度门控** — 减少误报，改动最小
3. **VLM 周期分析** — 替代硬编码 feedback 字符串，已有 DeepSeek API
4. **运动学特征** — 角速度/对称性，纯计算不需要新模型
5. **3D 化** — 根本解决投影畸变（Phase 2 双模型）
6. **本地分类器蒸馏** — 长期优化，等数据积累
