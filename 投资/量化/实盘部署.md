# 实盘部署

从回测到实盘，是量化最后也是最难的一步。理论上可行的策略，实盘中会遇到各种摩擦。

---

## 整体架构

```
数据层 → 信号层 → 执行层 → 风控层 → 监控层
  ↓         ↓        ↓        ↓        ↓
行情数据   因子计算  下单接口  仓位控制  报警/日志
财务数据   策略逻辑  订单管理  止损规则  绩效跟踪
```

---

## 1. 数据来源

### A股数据

| 来源 | 类型 | 费用 | 适合 |
|------|------|------|------|
| **Tushare** | 日线/财务/指数 | 免费（积分制） | 个人入门 |
| **AKShare** | 多数据源整合 | 免费 | 个人研究 |
| **Wind** | 机构级全量数据 | 昂贵（万元/年以上） | 专业机构 |
| **聚宽（JoinQuant）** | 日线+因子+回测 | 部分免费 | 策略开发 |
| **米筐（RiceQuant）** | 同上 | 部分免费 | 策略开发 |

### 数据注意事项

- **前复权 vs 后复权**：做回测用**后复权**（固定历史比较基准）；实盘看价格用**前复权**
- **停牌处理**：停牌期间不计算信号，复牌后流动性风险大，通常跳过
- **财务数据时效性**：季报/年报有公告延迟，必须用公告日而非报告期末日

## 3. 风控模块

**实盘中最重要的部分**，不做风控等于裸奔。

### 仓位管理

**Kelly 公式（理论上最优）**：
```
仓位比例 = (胜率 × 盈亏比 - 败率) / 盈亏比
```

**实操更常用**：等权重 / 按波动率倒数分配（低波动给更多仓位）

```python
# 波动率倒数仓位
vol = returns.rolling(20).std()
weight = (1 / vol) / (1 / vol).sum()  # 归一化
```

### 止损规则

| 类型 | 含义 | 参考设置 |
|------|------|---------|
| 单笔止损 | 单只股票亏损超过X% 清仓 | -8% ~ -15% |
| 组合止损 | 整体净值回撤超过X% 降仓 | -10% ~ -20% |
| 时间止损 | 持仓超过N天未盈利清仓 | 根据策略周期 |

### 黑天鹅保护

- 单股仓位上限（如 ≤ 5%，避免集中暴雷）
- 避开 ST 股、流动性极差的小票
- 重大事件前（年报季、政策窗口期）降低仓位

## 4. 执行与滑点控制

### 订单类型

| 类型 | 适用场景 |
|------|---------|
| 限价单 | 控制成本，适合流动性好的股票 |
| 市价单 | 确保成交，适合需要快速执行 |
| TWAP/VWAP | 大单拆分，减少冲击成本 |

### 减少冲击成本

- **分批建仓**：分 3-5 天完成建仓，不要一次性大买
- **避开开盘/收盘**：开盘15分钟和收盘前30分钟流动性最差
- **仓位上限 vs 日成交量**：单日买入不超过该股日成交量的 1-2%

## 5. 监控与复盘

### 每日监控

```
□ 策略净值是否正常
□ 有无异常持仓（买入了不该买的）
□ 有无未成交订单堆积
□ 数据源是否正常更新
```

### 绩效归因

定期回答这些问题：
1. 超额收益主要来自哪些因子/哪些股票？
2. 哪个时间段策略失效？原因是什么？
3. 实际执行成本和回测假设的差距是多少？

---

## 实盘 vs 回测的常见差距

| 问题 | 原因 | 应对 |
|------|------|------|
| 实盘收益远低于回测 | 冲击成本、滑点未计入 | 回测时加入现实成本假设 |
| 信号对但没买到 | 涨停板买不进、停牌 | 回测时过滤掉涨停日的买入信号 |
| 莫名持仓 | Bug 导致重复下单 | 下单前校验当前持仓 |
| 数据延迟 | 财报/行情延迟 | 用公告日，不用报告期末日 |

## 入门实践建议

### 第一步：用聚宽/米筐写第一个回测

```python
# 聚宽平台示例：最简单的动量策略
def initialize(context):
    set_universe('000300.XSHG')  # 沪深300成分股
    
def handle_data(context, data):
    # 过去20天涨幅
    prices = history(20, '1d', 'close', '000300.XSHG')
    momentum = prices.iloc[-1] / prices.iloc[0] - 1
    
    # 买入涨幅最大的10只
    top10 = momentum.nlargest(10).index
    for stock in top10:
        order_target_percent(stock, 0.1)
```

### 第二步：理解结果，刻意打破策略

- 换时间段测试
- 加入成本后是否还有超额收益？
- 是否有前视偏差？

## 关键认知

> **量化不是"写好策略然后躺着赚钱"，而是持续的研究、监控和迭代工作。**

因子会失效、市场会变化、代码会有 Bug。把量化视为一个需要持续维护的工程项目，而不是一个一次性产品。
