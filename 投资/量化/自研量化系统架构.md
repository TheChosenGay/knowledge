# 自研量化系统架构

从零搭建的 Python 量化回测系统 `quant_research`，覆盖数据→因子→信号→模拟→报告全流程。

---

## 设计原则

1. **模块化**：每个模块独立可测，通过明确的接口交互
2. **配置驱动**：策略通过 YAML 文件定义，不改代码
3. **真实费率**：滑点、佣金、印花税、整手约束全部建模
4. **CLI 入口**：统一命令行工具，一条命令跑完回测

## 核心模块详解

### 1. 数据层 (data/)

**数据源**：腾讯财经 HTTP 接口（`sources.py`），直接爬取日K线数据。

**存储**：DuckDB 做查询引擎 + Parquet 做持久化文件存储。DuckDB 适合分析型查询（OLAP），比 SQLite 更适合量化场景。

**Schema 校验**：`schemas.py` 验证每日 bar 数据的完整性（必须包含 open/high/low/close/volume/amount/turnover_rate 等字段），以及因子值数据的格式。

**状态字段**：`status_fields.py` 标记 ST 状态、涨跌停、停牌、上市天数等，这些在模拟引擎中用于过滤不可交易的股票。

### 2. 因子层 (factors/)

**因子定义** (`definitions.py`)：所有因子名集中管理，包含 21 个量价因子：

| 因子名 | 公式 | 窗口 |
|--------|------|------|
| momentum_252_21 | `close.shift(21) / close.shift(252) - 1` | 252日 |
| momentum_126_21 | `close.shift(21) / close.shift(126) - 1` | 126日 |
| reversal_20 | `close / close.shift(20) - 1` | 20日 |
| reversal_5 | `close / close.shift(5) - 1` | 5日 |
| reversal_3 | `close / close.shift(3) - 1` | 3日 |
| volatility_20/60/5 | `returns.rolling(N).std()` | 20/60/5日 |
| amount_mean_20/5 | `amount.rolling(N).mean()` | 20/5日 |
| turnover_mean_20/5 | `turnover.rolling(N).mean()` | 20/5日 |
| turnover_std_20/5 | `turnover.rolling(N).std()` | 20/5日 |
| volume_price_corr_20 | `corr(volume, close, 20)` | 20日 |
| amihud_illiquidity_20/5 | `mean(abs(return)/amount, N)` | 20/5日 |
| high_low_ratio_20/5 | `mean((high-low)/close, N)` | 20/5日 |
| close_to_high_20/5 | `close / rolling_max(high, N) - 1` | 20/5日 |

**计算实现** (`calculator.py`)：全部用 pandas 向量化计算，按 `asset_id` 分组后做 rolling 操作。核心模式：

```python
# 分组滚动计算（避免跨股票数据污染）
def _rolling_by_asset(values, asset_ids, window, method):
    grouped = values.groupby(asset_ids)
    rolling = grouped.rolling(window, min_periods=window)
    # ...
```

**标准化** (`normalizer.py`)：z-score 标准化 + 去极值（winsorize）。

### 3. 模拟引擎 (simulation/) — 最核心模块

**主循环** (`engine.py`)：逐交易日模拟。流程如下：

```
遍历每个交易日:
  1. 如果是调仓日 → 读取当天信号（排名Top N股票）
  2. 先卖后买（先释放现金）
  3. 每笔订单执行：
     - 检查停牌/涨跌停/ST/新股限制
     - 计算滑点价格 (open_price × (1 ± slippage_bps/10000))
     - 计算费用 (佣金+印花税+过户费)
     - 买入检查现金是否充足
     - 整手约束 (100股为单位)
  4. 计算当日市值和净值
  5. 风控检查 (动态回撤减仓)
  6. 记录 NAV、持仓、订单、成交、事件
```

**交易规则** (`rules.py`)：

```python
# 滑点：买入价 = 开盘价 × (1 + 5bps)，卖出价 = 开盘价 × (1 - 5bps)
def apply_slippage(side, open_price, slippage_bps):
    multiplier = 1 + slippage_bps / 10_000 if side == "buy" else 1 - slippage_bps / 10_000
    return open_price * multiplier

# 费用：佣金(双边万三,最低5元) + 印花税(卖出千一) + 过户费(万0.1)
def calculate_fees(side, gross_amount, ...):
    commission = max(gross_amount * 0.0003, 5.0)
    stamp_tax = gross_amount * 0.001 if side == "sell" else 0.0
    transfer_fee = gross_amount * 0.00001
    total_fee = commission + stamp_tax + transfer_fee

# 整手约束
def round_down_to_lot(shares, lot_size=100):
    return int(shares // lot_size * lot_size)
```

**涨跌停处理**：
- 股票代码判断：300/301→创业板20%, 688→科创板20%, 43/83/87/92→北交所30%, ST→5%
- 买入时如果开盘价触及涨停价 → 拒绝（买不到）
- 卖出时如果开盘价触及跌停价 → 拒绝（卖不掉）

**风控模块** (`risk.py`)：动态回撤减仓
- 净值从高点回撤 10% → 仓位降至 70%
- 净值从高点回撤 20% → 仓位降至 40%
- 净值从高点回撤 30% → 仓位降至 5%
- 支持恢复：净值回升后自动增加仓位

### 4. 组合评分 (portfolio/)

**多因子打分** (`scorer.py`)：
```python
# 每只股票的得分 = Σ(因子z-score × 权重 × 方向)
score = sum(zscore * weight * direction for each factor)
# 按得分排名，取Top N
```

## 策略配置格式

用 YAML 定义策略，不改代码：

```yaml
strategy:
  name: shortcycle_weekly_v3
  description: "短中周期混合因子 周度调仓"

universe:
  all_stocks: true
  limit: 300          # 取流动性最好的300只

range:
  start: "2021-07-01"
  end: "2025-05-21"
  adjust: qfq          # 前复权

factors:
  - name: reversal_5
    weight: 1.0
    direction: -1      # -1=做多因子值最小的
  - name: volatility_20
    weight: 1.0
    direction: -1

simulation:
  top_n: 30
  rebalance: weekly
  initial_cash: 1000000
  slippage_bps: 5.0
  commission_rate: 0.0003
  stamp_tax_rate: 0.001
  lot_size: 100
  cash_buffer: 0.02
  max_position_weight: 0.05
  risk_mode: dynamic_drawdown
  risk_stages: "0.10:0.70,0.20:0.40,0.30:0.05"

normalization:
  enabled: true
  neutralize: false

output:
  csv_dir: reports/simulations/shortcycle_weekly_v3
  markdown: reports/simulations/shortcycle_weekly_v3.md
```

## 技术选型理由

| 选择 | 理由 |
|------|------|
| DuckDB | 嵌入式 OLAP 引擎，分析型查询比 SQLite 快很多，适合因子计算 |
| Parquet | 列式存储，压缩率高，pandas 原生读写 |
| YAML 配置 | 人可读，策略参数一目了然 |
| dataclass | 配置对象不可变，防止意外修改 |
| 向量化 pandas | 避免 Python 循环，利用 numpy 底层加速 |
| 前复权 (qfq) | 保证历史价格连续性，回测基准一致 |

## 已知限制和改进方向

1. **数据覆盖**：目前只有日K线，没有分钟线、财报数据、龙虎榜等
2. **因子类型**：只有量价因子，没有基本面因子（ROE、PE、成长等）
3. **执行模型**：只用开盘价成交，未实现 TWAP/VWAP 算法
4. **股票池**：全市场取前300只，未按行业/市值分层
5. **行业中性化**：代码支持但当前策略未启用
